# Техническое задание

## Личный кабинет абонента регионального оператора связи «Север-Телеком»

### 1. Общие сведения

Оператор связи «Север-Телеком» (около 1,8 миллиона абонентов в шести областях) хочет заменить устаревший личный кабинет новым: баланс и детализация расходов, смена тарифа, подключение услуг, обращения в поддержку и уведомления. Срок — 7 месяцев, команда ориентировочно 10–12 человек. Коммерческие условия в этот документ не входят.

Состав команды перечнем не приводится, потому что часть людей нужна лишь на отдельных этапах. Кого и когда привлекать, видно из разделов ниже.

### 2. Цели проекта

Главная цель — снять нагрузку с контактного центра: сейчас около 40% обращений составляют вопросы, ответ на которые абонент мог бы найти сам. Вторая цель — сократить время смены тарифа с нескольких минут до нескольких секунд. Третья — подготовить основу для будущих сервисов оператора, не переписывая платформу заново.

### 3. Что остаётся как есть

Действующий кабинет написан на Angular и работает на MySQL; поддерживать его в рамках проекта не нужно, он будет выведен из эксплуатации после переключения абонентов. Прежние автоматические проверки на Selenium мы не переносим. Модуль биллинга на C# остаётся у вендора и нашей команде не передаётся. Скрипты выгрузки исторических данных на Python пишут аналитики заказчика, от исполнителя они не требуются.

Текущая шина сообщений на RabbitMQ после миграции отключается, и новых решений на ней не будет. Мониторинг инцидентов безопасности (SIEM) остаётся в зоне ответственности службы ИБ заказчика. Размещение в AWS обсуждалось, но не подходит. GraphQL для публичных интерфейсов сейчас не рассматривается.

### 4. Клиентская часть

Абонент видит баланс, детализацию расходов и подключённые услуги, меняет тариф и управляет услугами самостоятельно. Веб-кабинет разрабатывают трое фронтенд-разработчиков на React. Код фронтенда пишется на TypeScript; использование чистого JavaScript в новом коде запрещено. Сквозные тесты пишут сами фронтенд-разработчики на Playwright, отдельного человека на это не выделяем.

Желательно, чтобы интерфейс отвечал требованиям доступности WCAG 2.1 AA; фронтенд-разработчики учитывают это при вёрстке, но к первому релизу это не обязательно.

Дизайн интерфейсов делает UX/UI-дизайнер, он подключается на первом этапе.

### 5. Серверная часть

Серверную часть пара бэкенд-разработчиков уровня senior пишет на Java. Основной фреймворк — Spring Boot, бэкенд-разработчики работают в нём. Для обмена событиями между сервисами, скорее всего, возьмём Kafka — окончательно подтвердим по итогам пилота; подключать её будут бэкенд-разработчики.

Архитектор решения уровня senior проектирует взаимодействие сервисов через события и документирует архитектуру по модели C4. Границы ответственности сервисов фиксируются до начала активной разработки.

### 6. Данные и интеграции

Системный аналитик описывает интеграцию с биллингом и CRM оператора: форматы сообщений, коды ошибок и правила повторной отправки. Эксплуатацию PostgreSQL — резервные копии, репликацию, обновления — берёт на себя DevOps-инженер. По возможности — витрины для отдела маркетинга в ClickHouse; проектирует их дата-инженер.

### 7. Развёртывание

Размещение — Yandex Cloud, так требует политика компании по хранению данных в России. Все сервисы запускаются в кластере Kubernetes. Инфраструктура описывается кодом на Terraform, окружения воспроизводятся одной командой. Контейнеризация — разумеется, Docker, как у всех. Дашборды по возможности собираем в Grafana.

### 8. Безопасность

Инженер по информационной безопасности настраивает единый вход абонентов и сотрудников по OIDC и ролевую модель доступа. Перед релизом приложения проверяются по OWASP Top 10. Персональные данные абонентов хранятся только на территории России.

### 9. Организация работ

Проектом руководит один руководитель проекта, работа ведётся по Kanban: доска, ограничение числа задач в работе, еженедельный обзор. В прошлом проекте использовали Scrum, здесь отказались: потоки задач слишком разнородные.

На этапе обследования работает бизнес-аналитик. На втором этапе в команду подключается тестировщик.

Этапы: обследование и проектирование — первые два месяца; разработка кабинета и серверной части — месяцы с третьего по пятый; пилот и поэтапное переключение абонентов — месяцы с шестого по седьмой.

### 10. Приёмка

Приёмка проходит в три этапа: на стенде, на одной пилотной области и после подключения остальных областей. Критерии приёмки по каждому этапу согласуются с владельцем проекта со стороны заказчика заранее и фиксируются в протоколе.

### 11. Передача результатов

По окончании работ исполнитель передаёт исходный код, документацию по развёртыванию и руководство для дежурных. Гарантийный срок составляет 12 месяцев с момента подписания акта приёмки.
